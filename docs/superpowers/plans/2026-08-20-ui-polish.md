**Architecture:** Presentation layer only. Two new wrappers (`Button`,

tuple, or saved-JSON changes.

Vitest, TypeScript 7. Format with Biome (`npm run format`), print width

**Branch:** `feat/ui-polish` off `main` at `cdaeb09`. Baseline: 102 tests

## Global Constraints

- Solid 2.0 APIs only. Forbidden: `createResource`, `batch`,
  `startTransition`, `useTransition`, `on`, `createComputed`, `produce`,
  `createMutable`, `onMount`, `classList`, `use:` directives, `<Index>`.
- `<For>` children receive accessors: `{(item) => …}`.
- No third-party component, form, or icon libraries. Native HTML +
  Tailwind wrappers in `src/components/ui/`.
- All domain math stays in `src/lib/gear/`. UI never contains formulas.
- Never store derived values in signals/stores — always `createMemo`.
- Config changes go through `navigate({ search, replace: true })`.
- **Search `v` stays `1`. No search-param, compare-tuple, or saved-JSON
  changes in this plan.** Any task that finds itself editing
  `src/lib/search.ts` or `src/lib/state/saved-store.ts` has gone wrong.
- **No `deriveMetrics` or `src/lib/gear/` behavior changes.** Numbers on
  screen must be byte-identical before and after, except preset chip
  subtitles when `circ` is set (Task 4, intentional).
- `bg-accent` is never paired with `text-paper`. Accent as text is always
  `text-accent-ink dark:text-accent`.
- Use `outline`, never `ring`/`box-shadow`, for focus so it survives
  `overflow-hidden` parents.
- Prefer Solid's native `class` array/object form (`class={["a", {b:
  cond}]}`) as `MetricCard.tsx:17` does, not string concatenation.
- `import type { JSX } from "@solidjs/web"` — that is the repo's path
  (`Tooltip.tsx:1`).
- No new npm dependencies. Do not bump TanStack or `solid-js`. Do not
  remove `package.json` `overrides`.
- Test count may only go up from 102. Never delete a test to make a
  change pass.
- Run `npm run format` before every commit; Lefthook runs Biome on commit
  and Biome + typecheck on push.

```tsx
  ariaLabel?: string;

      class={[
```

`SegmentedControl.tsx`. The radio is `sr-only` and the sibling `<span>`
carries every visual state through `peer-*` variants. Native radios give
arrow-key navigation and single-select semantics for free — no keyboard
handler is written by hand.

```tsx
import { For } from "solid-js";

export interface SegmentedControlOption<T extends string> {
  id: T;
  label: string;
}

export interface SegmentedControlProps<T extends string> {
  legend: string;
  name: string;
  options: readonly SegmentedControlOption<T>[];
  value: T;
  onChange: (value: T) => void;
}

export function SegmentedControl<T extends string>(
  props: SegmentedControlProps<T>,
) {
  return (
    <fieldset class="m-0 flex min-w-0 overflow-hidden rounded border border-ink/15 p-0 dark:border-paper/20">
      <legend class="sr-only">{props.legend}</legend>
      <For each={props.options} keyed={(option) => option.id}>
        {(option) => (
          <label class="flex">
            <input
              type="radio"
              class="peer sr-only"
              name={props.name}
              value={option().id}
              checked={props.value === option().id}
              onChange={() => props.onChange(option().id)}
            />
            <span class="cursor-pointer px-2.5 py-1 text-sm transition-colors motion-reduce:transition-none peer-checked:bg-accent peer-checked:text-ink peer-focus-visible:outline-2 peer-focus-visible:outline-offset-2 peer-focus-visible:outline-accent-ink dark:peer-focus-visible:outline-accent">
              {option().label}
            </span>
          </label>
        )}
      </For>
    </fieldset>
  );
}
```

**No `first:rounded-l` / `last:rounded-r` on the span.** `first:` compiles
to `:first-child`, and the span is its label's *second* child — the
`sr-only` input is first — so those variants could never match.
`overflow-hidden rounded` on the fieldset clips the selected fill's
square corners instead, which is the actual defect being fixed. Confirm
visually at `npm run dev`.

Rewrite `UnitToggle.tsx` and `ThemeToggle.tsx` as thin callers holding
only their option list and store wiring. `OPTIONS` stays module-level and
typed `readonly SegmentedControlOption<Units>[]` /
`SegmentedControlOption<Theme>[]`. Each passes a distinct `name`
(`"units"`, `"theme"`) so the two radio groups never collide.

```diff

+fireEvent.click(getByRole("radio", { name: "Imperial" }));
```
